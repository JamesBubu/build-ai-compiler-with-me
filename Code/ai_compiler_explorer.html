Computation Graph
A DAG where nodes are operations and edges are tensors. The graph is constructed at definition time — no computation occurs until you explicitly evaluate it (lazy / deferred execution).
x = Variable("x") # no value yet z = ReLU(Add(x, y)) # build structure evaluate(z, {x:[1,2,3]}) # execute
Node Types
Variable
Symbolic inputs. Shape known at compile time; value supplied only at runtime.
Constant
Fixed tensors (weights, biases). Both shape and value known at compile time — prime candidates for constant folding.
Operators
Pure functional compute nodes: Add, Mul, ReLU, MatMul. Output depends only on inputs.
Compiler Passes
Shape Inference
Traverses the graph, deriving output shapes without executing. Required before memory can be allocated.
Variable x → shape [3] Add(x, y) → shape [3] ← derived ReLU(add) → shape [3] ← propagated
Constant Folding
If every input to an op is a Constant, pre-compute the result and replace the op with a new Constant node. Reduces runtime work.
Const a=[1,2], Const b=[3,4] Add(a,b) → folded to Const [4,6]
Dead Code Elimination
Traces backward from output nodes. Nodes unreachable from any output contribute nothing — remove them.
Industry Context
The same passes run at scale in TVM, MLIR, XLA, and torch.compile (Dynamo + Inductor). The IR concepts are identical — production compilers add GPU codegen, loop tiling, quantization, and distributed placement on top.
